# FleetOps Back-Office Platform

Generated by the CerebrumDev factory role runner.

A staff-only back office for a car rental company running 4 branches with
about 20 people (2 sales agents, 2 accountants and 1 branch manager per
branch). It is **not** customer facing: every route is internal, every answer
carries the authority layer that produced it, and nothing leaves the box
except email.

## What this is

A standalone platform. Every capability runs in-process: handlers invoke
blocks that were vendored into `vendor/blocks/` at build time, through
`app/dispatch.py`. There is **no call back to a block store at runtime** — the
platform runs with the factory switched off (`P1`).

## Capabilities

| capability | what it does |
|---|---|
| `fleet_registry` | every vehicle: plate/VIN, branch, category, state (available / rented / in_maintenance / off_road), mileage, service history |
| `rental_contract_management` | reservations, contracts, pickup/return, extensions, deposits, damage notes, per-vehicle availability key so the same car is not double-booked |
| `maintenance_scheduling` | preventive schedules by date or mileage, workshop jobs, downtime cost, reminder window before a vehicle goes off-road |
| `pricing_and_rate_cards` | category/branch/season/duration rate cards, mileage, fuel, late-return and extras charges, deposits, price-override reason for audit |
| `invoicing_and_deposits` | invoices, credit notes, deposit held/released, outstanding balance, settlement state |
| `multi_branch_rollup` | per-branch revenue, cost, profit and profit margin, plus the company rollup |
| `reporting_analytics` | utilisation, revenue, maintenance cost, overdue returns, unpaid invoices — each with its band and alert |
| `audit_trail` | contract changes, deposit releases and price overrides with an entry digest over the record |

Roles are enforced in `app/security.py` (sales agent / accountant / branch
manager, branch scope from the principal, never from the payload).

## Run it

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --reload      # GET /health -> 200
```

```bash
.venv/bin/python -m pytest tests -m "not pilot"   # code-phase gate
.venv/bin/python -m pytest tests                  # includes pilot coverage
.venv/bin/python scripts/release_gate.py          # code-phase verdict
.venv/bin/python scripts/acceptance.py            # 13 measured Gate checks
.venv/bin/python scripts/bench.py                 # 200 requests, p95
```

The console is served at `/` (`app/static/index.html`). It discovers
capabilities from `GET /v1/capabilities`, reads each capability's field list
from `GET /v1/schema`, and drives the real routes: create a record, list it,
read it back, ingest a document and query it. Every answer is shown with its
authority label.

The typed source of that same console is `frontend/src/App.tsx`. It is not
needed to deploy — the image serves the checkout's single-file console and
there is no node toolchain in the image — but a team that prefers a bundled
build can run:

```bash
cd frontend && npm install && npm run build   # writes app/static/ + app/static/assets
```

Assets are mounted at `/assets`, so a bundle built this way is served, not
decoration.

Data lands in `$STORAGE_PATH/platform.db` (default `./data`). Schema is Alembic
(`alembic upgrade head` at deploy, and in the FastAPI lifespan). `app/store.py`
does not `CREATE TABLE`; `app/db.py` is the one place that decides Postgres vs
SQLite.

## Settings the operator must set before use

Country, currency and tax rates are the customer's values. The brief for this
build names none of them, so the platform invents none: amounts stay bare
numbers until these are set, and `app/settings.py` refuses to label money
without `CURRENCY`. `GET /v1/settings` reports which are set (names only,
never a secret's value).

| setting | meaning | default |
|---|---|---|
| `STORAGE_PATH` | the one storage root (database, backups, outbox, RAG corpus, block files) | `./data` |
| `PLATFORM_TOKEN` | bearer token for every `/v1` data route | `dev-local-token` (dev only) |
| `TENANT_TOKENS` | `token:tenant_id,...` for additional tenants | unset |
| `SESSION_TTL_SECONDS` | lifetime of the staff session cookie a token-authenticated caller is issued | `28800` (8h) |
| `SESSION_COOKIE_SECURE` | `1` when the console is served over TLS, so the session cookie is TLS-only | unset (plain-http pilot) |
| `CURRENCY` | ISO 4217 code used when money is printed | **none — required before use** |
| `TAX_VAT_RATE` | VAT/GST as a decimal fraction | **none — required before use** |
| `TAX_SALES_TAX_RATE` | sales tax as a decimal fraction | **none — required before use** |
| `TAX_WITHHOLDING_RATE` | withholding as a decimal fraction | **none — required before use** |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, `SMTP_USERNAME`, `SMTP_PASSWORD` | the mail relay (the platform's one live outbound connector) | unset: notices are rendered and queued, nothing is claimed as sent |
| `DATABASE_URL` | Postgres URL; unset means SQLite at `$STORAGE_PATH/platform.db` | unset |
| `DATA_DIR` | where the vendored block runtime writes its files | pinned under `$STORAGE_PATH/blocks` |
| `BACKUP_DIR` | where backups land | `$STORAGE_PATH/backups` |
| `RATE_LIMIT_PER_MINUTE` | per-client `/v1` request ceiling | `600` |
| `APP_REVISION`, `APP_MARK` | deploy identity reported by `/health` | `rev-n` / `baseline` |
| `SENTRY_DSN` | error reporting | unset: reporting stays local |

`.env.example` documents the same list.

## HTTP surface

Kernel job descriptions: `GET /v1/jobs`, `/v1/catalog`, `/v1/inventory`,
`/v1/capabilities`, `/v1/gates`, `/v1/provenance` — these inspect the
manufactured platform and execute nothing.

Per capability: `POST /v1/{capability}`, `GET /v1/{capability}`,
`GET|PUT|DELETE /v1/{capability}/{id}`. Plus `GET /v1/schema`,
`GET /v1/settings`, `GET /metrics`, `GET /health`, `GET /` (console).

Retrieval (optional at launch — nothing to upload today):
`POST /v1/rag/ingest`, `GET|POST /v1/rag/query`.

Rules the routes enforce: no token → `401`; missing required field → `422`
naming the field; a value outside the declared vocabulary (status is exactly
`open | in_progress | closed`) → `422`; a reserved client key (`tenant_id`,
`tenant`, `action`) → `422`; another tenant's record → `404`, never `403`.

Staff sessions: a caller that authenticates with `PLATFORM_TOKEN` receives an
opaque session cookie (`fleetops_session`), so the console authenticates once
and keeps working instead of re-sending the token on every call. The cookie
holds a server-side session id — never the token — bound to exactly the tenant
that token resolved to, so it can only reproduce that tenant's rows. A request
with no credential at all, or with a session id the platform never issued, is
still refused `401`. Sessions are process-local and bounded (1024 live), and
their lifetime is `SESSION_TTL_SECONDS`.

`docs/openapi.json` (and the root `openapi.json`) is generated from the
served app.

## Data, backup, restore

`app/db.py` decides the database once; `app/store.py` owns the SQL. The
vendored block runtime's own files are pinned under `$STORAGE_PATH` so no
second persistence root appears beside the mounted disk.

```bash
sh scripts/backup.sh          # online SQLite backup into $BACKUP_DIR, retention 14
```

`tests/test_data_lifecycle.py` and `tests/test_backup_restore.py` run the
backup → wipe → restore drill and count the rows back. A backup nobody has
restored is a file, not a backup. Same-disk `BACKUP_DIR` protects against
logical loss only; point it at another volume if disk loss is in scope.

## Notifications

Email only. `app/notifications.py` renders each maintenance-due /
rental-overdue / deposit-release / invoice-overdue notice into
`$STORAGE_PATH/notifications/outbox.jsonl`, and — when `SMTP_HOST` is set —
makes a real SMTP round trip and records whether it was sent. Without a relay
the notice stays queued and the record says `sent: false`.

## Vendor blockers (named, not stubbed)

Three blocks the plan's roster assigns cannot load in this checkout. They are
**not** declared in any handler's `BLOCK_IDS` and are not replaced by stubs;
each defect, reproduction and remedy is recorded in
`docs/vendor_block_defects.json`:

| block | what ships instead |
|---|---|
| `notification` | `app/notifications.py` (outbox + optional SMTP relay) |
| `knowledge` | `app/rag_routes.py` over `app/retrieval.py` |
| `document_engine` | the capabilities that would parse documents do not; nothing to upload at launch |

`app/dispatch.py` resolves blocks from `vendor/blocks/` and, in a checkout that
has not been vendored yet, from `CEREBRUM_BLOCKS_ROOT` — it reads, never writes.

## Layout

| path | purpose |
|---|---|
| `app/main.py` | FastAPI app factory, lifespan migrations, `/health`, `/metrics`, console |
| `app/routes.py` | capability HTTP surface + kernel job routes |
| `app/actions/` | one handler per capability (dispatch envelope, `BLOCK_DEFAULT_ACTIONS`) |
| `app/dispatch.py` | local block dispatch, harvested block contracts |
| `app/models.py` | domain models: `FIELDS`, `CONSTRAINTS`, `from_dict`/`to_dict` |
| `app/db.py`, `app/store.py` | one connection factory; tenant-scoped SQL |
| `app/settings.py` | operator settings, no invented values |
| `app/security.py`, `app/authority.py` | roles and branch scope; precedence.v1 labels |
| `app/formulas.py`, `app/retrieval.py`, `app/llm.py` | arithmetic, retrieval, offline LLM adapter |
| `app/notifications.py` | email outbox and the SMTP connector |
| `alembic/versions/` | `0001_baseline` (one table per capability, `tenant_id`), `0002_lifecycle_audit` |
| `tests/` | code-phase + pilot suite, negative-floor cases |
| `scripts/` | `release_gate.py`, `acceptance.py`, `backup.sh`, `bench.py`, `entrypoint.sh`, `rollback.sh` |
| `app/static/index.html`, `frontend/src/App.tsx` | the staff console |
| `Dockerfile`, `render.yaml`, `Procfile` | deploy surface (healthcheck, migrations on boot) |
